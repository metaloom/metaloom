Loom exposes a GraphQL API for flexible, nested queries over the asset data model — fetch an asset
together with its components and locations in a single request, selecting exactly the fields you
need. The same API also answers cross-entity search queries, so a client never has to list and
filter on its own.

== Endpoint

----
POST http://<host>:8092/api/v1/graphql
----

The endpoint accepts a JSON body with `query`, and optional `operationName` and `variables` fields,
and returns the standard GraphQL `{ "data": ..., "errors": ... }` response shape.

== Authentication & Authorization

The GraphQL endpoint reuses the REST authentication stack — a valid JWT bearer token (HttpOnly
cookie or `Authorization` header) is required; unauthenticated requests are rejected with `401`
before the query is parsed. Obtain a token via the link:../authentication/[Authentication] flow.

Authorization is enforced per field. Each resolver checks the caller's permissions:

[options="header",cols="2,1"]
|===
| Field | Required permission
| `Query.asset`, `Query.assets` | `READ_ASSET`
| `Asset.imageComponents` / `videoComponents` / `audioComponents` | `READ_ASSET`
| `Asset.locations` | `READ_ASSET_LOCATION`
| `Query.search` | `READ_SEARCH`, plus the read permission of each entity type searched
|===

A denied field surfaces a GraphQL error with a `code` extension (`UNAUTHENTICATED` when no
permission context is present, `FORBIDDEN` with the missing `permission` otherwise).

== Example Queries

Fetch a single asset with all of its components and locations:

[source,graphql]
----
query GetAsset($uuid: ID!) {
  asset(uuid: $uuid) {
    uuid
    filename
    mimeType
    size
    imageComponents { uuid dominantColor width height }
    videoComponents { uuid source }
    audioComponents { uuid source }
    locations { uuid path libraryUuid mimeType }
  }
}
----

List all assets with a minimal field selection:

[source,graphql]
----
query ListAssets {
  assets {
    uuid
    filename
    mimeType
    size
  }
}
----

Search across everything at once — assets, transcripts, tags, people, collections and more — and
select only the fields you want to render:

[source,graphql]
----
query Search($q: String!) {
  search(q: $q, types: [ASSET, TRANSCRIPT], limit: 10) {
    totalHits
    warnings
    hits {
      entityType
      entityUuid
      assetUuid
      title
      subtitle
      score
      highlights
    }
  }
}
----

A few things worth knowing about `search`:

* Entity types you are not allowed to read are dropped from the query rather than failing it. Every
  dropped type is named in `warnings`, so an incomplete answer is never mistaken for an empty one.
  If you may read none of the types you asked for, the query is rejected instead.
* `highlights` is only computed when you select it — the highlighter re-reads the matched documents,
  so you do not pay for snippets you did not ask for.
* WARNING: `highlights` fragments are *not* safe HTML. Matches are wrapped in `<b>` markers and the
  surrounding text comes through verbatim from user-supplied filenames, tags and transcripts. Parse
  the fragments and re-render the matches yourself; never insert them into a page as markup.
* Asking for a mode the server cannot serve returns an error naming the reason, rather than quietly
  answering with a different one.
