Kubernetes is the supported production deployment path for Loom. The full walkthrough — service
account, RBAC for the chat's coding sandbox, quotas, NetworkPolicy and the Cortex worker pools — is in
the link:../../playbooks/kubernetes/[Kubernetes playbook].

== Status

WARNING: `loom/helm` in the source repository is currently a **placeholder**: it contains a README and
no chart. There is no `helm install` to run yet.

Until a chart ships, deploy with the manifests in the
link:../../playbooks/kubernetes/[Kubernetes playbook], or wrap them in a chart of your own. That page
also carries a suggested `values.yaml` layout, so a chart written now stays close to the one that will
be published.

== What a Chart Must Cover

Two things are easy to miss when packaging Loom, and both are called out in the playbook:

* The `/config` volume holds `loom.yml` and `keystore.jceks` — the JWT signing key. It must be
  persistent, or every issued token stops verifying after a restart.
* Enabling the coding sandbox (`LOOM_AGENT_SANDBOX_ENABLED`) is only complete together with the Role,
  RoleBinding, ResourceQuota, LimitRange and NetworkPolicy for the runner namespace. Templating the
  environment variable alone produces a deployment that cannot create runners, or creates unconstrained
  ones.

See link:../artifacts/[Artifacts] for the published Maven and container coordinates.
