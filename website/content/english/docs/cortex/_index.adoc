MetaLoom // *Cortex* is the media processing engine of the MetaLoom platform.
It analyses media files — images, videos, audio, documents — and extracts metadata such as hashes,
thumbnails, fingerprints, face embeddings, transcripts, captions and OCR text.

== Cortex is a Daemon that Serves Nodes

Cortex runs as a **long-running worker daemon**, not a one-shot CLI batch tool. On startup it opens a
persistent WebSocket to a Loom server, **registers** itself and the node kinds it can run, and then
waits for work. Loom *pushes* tasks down that connection; Cortex never polls.

Crucially, **the pipeline graph lives on Loom, not on Cortex**. Loom owns the DAG and dispatches
individual tasks — a source task to enumerate media, then one node task per graph node per item — to
whichever registered Cortex instance is allowed to run that kind. Cortex only ever sees one node (or
affinity segment) at a time and answers with a result. See link:../pipeline/[Pipeline Mechanism] and
link:../interaction/[Loom & Cortex Interaction].

This lets you scale processing horizontally: run many Cortex instances, each advertising a subset of
node kinds (e.g. a GPU box that only runs `facedetect` and `whisper`), and Loom routes tasks
accordingly.

== Modes of Operation

*Online mode* :: Cortex connects to a Loom server, registers its capabilities, and executes source /
node / segment tasks dispatched by Loom's pipeline engine. Results are written back to Loom over the
REST API. This is the primary deployment.

*Offline mode* :: With no Loom host configured, Cortex runs standalone against local files. Loom-bound
features (registration, task dispatch, result sync) gracefully degrade to no-ops. Useful for
air-gapped pre-processing.
