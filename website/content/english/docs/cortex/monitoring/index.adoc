= Monitoring API

A Cortex worker runs a lightweight monitoring HTTP server exposing **liveness** and **readiness**
endpoints, designed for Kubernetes probes and load balancers. Loom exposes its own health check on the
REST API.

== Cortex Health Server

The Cortex daemon starts a small Vert.x HTTP server (separate from any Loom traffic) on port `8093` by
default, configurable with the `CORTEX_MONITORING_PORT` environment variable.

[options="header",cols="1,1,3"]
|===
| Endpoint | Status | Meaning
| `GET /api/health` | always `200` while the process is up | **Liveness.** JSON `{ "status": "up", "loom": { … } }` — the process is alive.
| `GET /api/ready` | `200` when ready, else `503` | **Readiness.** Ready means the worker is *connected to Loom **and** registered*. JSON `{ "status": "ready" \| "not_ready", "loom": { … } }`.
|===

NOTE: The legacy paths `GET /health` and `GET /ready` are also served for backward compatibility with
existing probes.

The embedded `loom` object reports the worker's connection to Loom:

[source,json]
----
{
  "status": "ready",
  "loom": {
    "configured": true,
    "connected": true,
    "registered": true,
    "host": "loom.internal",
    "port": 8092,
    "reconnectAttempts": 0,
    "lastConnectedAt": 1750000000000,
    "lastHeartbeatAckAt": 1750000009000,
    "error": null
  }
}
----

In offline mode (`configured: false`) the worker reports `up` for liveness but stays `not_ready`, since
there is no Loom to register with.

=== Kubernetes Probe Configuration

Map liveness onto `/api/health` and readiness onto `/api/ready`:

[source,yaml]
----
livenessProbe:
  httpGet:
    path: /api/health
    port: 8093
  initialDelaySeconds: 10
  periodSeconds: 15

readinessProbe:
  httpGet:
    path: /api/ready
    port: 8093
  initialDelaySeconds: 5
  periodSeconds: 10
----

=== Changing the Port

[source,bash]
----
CORTEX_MONITORING_PORT=9090
----

== Loom Health Check

The Loom server exposes a health check on its REST API:

----
GET /api/v1/health
----

[source,json]
----
{
  "status": "UP",
  "version": "1.0.0-SNAPSHOT",
  "database": "UP",
  "timestamp": "2026-07-25T20:00:00Z"
}
----

It verifies database connectivity; if the database is unreachable, `database` is `DOWN` and `status`
becomes `DEGRADED`. See link:../../loom/rest-api/[REST API].

== Metrics (planned)

A dedicated **Prometheus metrics** endpoint and a separate Loom monitoring port
(`LOOM_SERVER_MON_PORT`, default `8989`) are reserved for future use — the Loom `monitoring` module is
currently a placeholder and neither Loom nor Cortex serves a `/metrics` endpoint yet. Until then, use
the health/readiness endpoints above for probing and availability checks.
