---
title: Loom Sync
---

The Loom sync node is a **sink**: it accumulates hash results and writes them back to the Loom
backend in batches, keeping the number of REST calls low on large runs. It has one input port per
algorithm, and each port accepts only that algorithm's hash type — so which column a hash lands in
follows from the connection you drew, never from what an upstream node happens to be called.

[cols="1,3"]
|===
| Kind | `loom`
| Applies to | Any file
| Input ports | `md5`, `sha256`, `sha512` — each optional, each accepting only its own hash type. Connect the `hash` port of the matching link:../hash/[hash] node
| Output ports | None — the node has the side effect of bulk-updating the `asset` rows
| Requirements | A Loom connection (`LOOM_HOST` / `LOOM_PORT` / `LOOM_TOKEN`). CPU only.
| Persists to | `asset` hash columns via a bulk update (batches of 50)
|===

NOTE: Per-node persistence now also writes hash columns directly, so the `loom` node overlaps that
path. It remains useful as an explicit batched hash sink.

== Configuration

No custom options beyond the common node flags.

== Use Cases

* **Efficient bulk hash sync** — flush many assets' hashes to Loom in batches during a large scan.
