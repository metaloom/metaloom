= Loom & Cortex Interaction

Loom is the brain; Cortex is the muscle. Loom stores assets, owns pipeline definitions and **drives**
processing runs; Cortex is a fleet of worker daemons that register with Loom and execute the individual
tasks Loom hands them.

== Architecture Overview

----
┌───────────────────────────────────────────────────┐
│  Loom (Media Asset Management Server)              │
│                                                   │
│  REST API + WebSocket + UI (:8092)  gRPC (:8091)  │
│  PostgreSQL database                              │
│  Pipeline definitions (versioned in DB)           │
│  Pipeline run engine — owns the DAG, tracks runs  │
└───────────────┬───────────────────────────────────┘
                │  Processor WebSocket (/api/v1/processors/ws)
                │   ▲ REGISTER + results     ▼ SOURCE/NODE/SEGMENT tasks
                │  REST data plane (result payloads)
                ▼
┌───────────────────────────────────────────────────┐
│  Cortex worker(s)  (Media Processing Daemon)      │
│                                                   │
│  Monitoring API (:8093)                           │
│  Node runtime — runs one task at a time           │
│  Advertises the node kinds it can run             │
└───────────────┬───────────────────────────────────┘
                │  reads media files (shared mount)
                ▼
           /media/assets/...
----

Two planes connect the two components — do not confuse them:

[options="header",cols="1,1,2"]
|===
| Plane | Transport | Carries
| Control | Processor WebSocket (`/api/v1/processors/ws`) | Registration, heartbeats, task dispatch (source/node/segment), task results, live tracking events.
| Data | REST (`LoomClient`) | The durable result payloads written back into Loom, keyed by asset.
|===

Cortex always dials *out* to Loom on port `8092`; **Loom never connects to Cortex.**

== Online Mode

An online Cortex worker:

. *Registers* — opens the processor WebSocket, authenticates (`?token=<jwt>`), and announces the node
  kinds it is willing to run. Loom persists it as a durable `cortex_instance`.
. *Waits for work* — Loom's pipeline engine dispatches a **source task** to enumerate media, then a
  **node task** per graph node per item (affinity work goes out as **segment tasks**).
. *Runs one task at a time* — the worker executes the requested node and replies with the outcome
  (`COMPLETED` / `FAILED` / `SKIPPED`) plus outputs for downstream nodes.
. *Persists results* — the worker writes the durable payload to Loom over REST (see
  link:../cortex/examples/[persistence path]).
. *Streams progress* — tracking events flow back over the WebSocket; Loom re-broadcasts them to UI
  clients on `/api/v1/pipelines/events/ws`.

Loom, not the worker, decides what runs next. Every dispatched task gets exactly one result — a node
that throws is reported `FAILED`, never dropped.

=== Connecting Cortex to Loom

[source,bash]
----
LOOM_HOST=loom.internal LOOM_PORT=8092 LOOM_TOKEN=<jwt> \
  docker run --rm -e LOOM_HOST -e LOOM_PORT -e LOOM_TOKEN metaloom/cortex-server:latest
----

See link:../cortex/configuration/[Cortex Configuration] and link:../cortex/containers/[Cortex Containers].

== Offline Mode

With no Loom host reachable, Cortex runs standalone against local files:

* No Loom server required; registration, task dispatch and result sync degrade to no-ops.
* Extracted metadata is stored in the local meta-path (default `~/.cache/metaloom/cortex/meta`) and
  xattr.
* Useful for pre-processing large archives, air-gapped environments, or development.

== Deployment Patterns

[options="header",cols="1,2"]
|===
| Pattern | Description
| *Worker Deployment* | One or more Cortex replicas run as a long-lived `Deployment`; scale replicas to add capacity.
| *Specialised pool* | A separate Cortex Deployment advertises only heavy kinds (e.g. `facedetect`, `whisper`) and is scheduled onto GPU nodes; Loom routes those kinds to it.
| *Side-car* | Cortex runs next to Loom in the same compose stack for small setups.
| *Standalone* | Cortex runs offline with no Loom server; results stay local.
|===
