# Specification Rules

* Include progress
* Write the specification in a way so that it is useful for an AI Coding Agent
* Include Test Setup for the feature / specification
* Other points you deem useful for an AI Coding Agent to work on the specification
* Include a "Progress Assessment" section with checkboxes (`- [x]` for done, `- [ ]` for todo) so AI agents can identify work items
* Include cross-references to other spec files using relative links (e.g. `[RESTAPI.md](../loom/RESTAPI.md)`) to avoid duplicating content
* Include a "Key Classes Reference" table mapping class names to their package and purpose, so AI agents can locate code quickly
* Include architecture diagrams using Mermaid or ASCII art to visualize component relationships
* Include environment variable tables for all configurable settings with their defaults
* Include a "Conventions and Gotchas" section highlighting non-obvious patterns, common pitfalls, and things to avoid
* Include a "Where do I find ...?" cheat sheet table mapping concepts to file paths
* When multiple subsystems exist, clearly delineate which subsystem is covered by which spec file to avoid duplication
* Include the GIT HEAD REVISION of the checkout and Current Date/Time in the footer of the documentation file.
